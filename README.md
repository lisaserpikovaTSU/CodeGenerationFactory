# Расширение реализации классов, обеспечивающих генерацию кода

Переработка реализации классов, обеспечивающих генерацию кода, направленная на расширение возможностей генерации на нескольких языках программирования.  

---

## 1. Постановка задачи

Расширить предоставленную реализацию (генерация кода C++), чтобы обеспечить генерацию программ на языках программирования С#, Java.  

**Требования к реализации:**
- Добавить модификаторы классов и методов
- Для решения задачи применить паттерн "Абстрактная фабрика"  

---

## 2. Предлагаемое решение

### 2.1 Общая идея

В решении применен порождающий паттерн "Абстрактная фабрика".  

Программа строит представление экземпляра куска кода в виде дерева **класс -> метод -> операторы**.  

Корень дерева - абстрактный класс Unit, от которого наследуются:
 - ClassUnit
 - MethodUnit
 - PrintOperatorUnit  

Конкретная реализация зависит от языка(C++/C#/Java) и создается соответствующей конкретной фабрикой через общий интерфейс ICodeFactory. Класс CodeGenerator выступает клиентом фабрики и строит код не завися от языка.

## 3. Тестирование

### Входные данные  

Входными данными для класса CodeGenerator являются:

- Имя класса
- Имя метода, тип возвращаемого значения, флаги-модификаторы метода, модификатор доступа
- Текст для оператора печати
- Конкретная фабрика (определяет целевой язык)   

### Тестирование фабрики C++ (CppCodeFactory)

**Случай 1**: Генерация класса с одним статическим публичным методом.
Результат: Корректный код C++ с ключевыми словами static, соответствующими отступами и printf.

**Случай 2**: Генерация класса с виртуальным константным приватным методом.
Результат: Корректный код C++ с ключевыми словами virtual, const и модификатором доступа private.

**Случай 3**: Пустое тело метода.
Результат: Корректный код метода с пустым телом { }.

### Тестирование фабрики C# (CSharpCodeFactory)

**Случай 4**: Генерация публичного класса со статическим методом.
Результат: Корректный код C# с ключевыми словами public, static и Console.WriteLine.

**Случай 5**: Генерация internal-класса с виртуальным приватным методом.
Результат: Корректный код C# с модификатором internal class, virtual и private.

**Случай 6**: Генерация класса без модификатора доступа.
Результат: Класс генерируется с модификатором по умолчанию (private для членов класса в C#).

### Тестирование фабрики Java (JavaCodeFactory)

**Случай 7**: Генерация класса со статическим публичным методом.
Результат: Корректный код Java с public static, System.out.println и фигурными скобками в стиле Java.

**Случай 8**: Генерация public abstract класса с абстрактным protected методом.
Результат: Корректный код Java с модификаторами public abstract class, protected abstract методом.

**Случай 9**: Генерация package-private класса (модификатор NONE).
Результат: Имя класса без модификатора, члены с package-private доступом (без ключевого слова).

### Тестирование общих сценариев

**Случай 10**: Создание нескольких методов с разными модификаторами доступа в одном классе.
Результат: Методы группируются по модификаторам доступа в порядке объявления, каждый со своим отступом.

**Случай 11**: Передача некорректного значения флага доступа (выход за границы массива ACCESS_MODIFIERS).
Результат: Используется модификатор доступа по умолчанию (PRIVATE или PACKAGE_PRIVATE), исключение не выбрасывается.
